# Backend Report: End-to-End Integration

## 1. What Was Built
- **Express Backend:** Secured with Helmet, CORS, and Express Rate Limiting.
- **Firebase Admin SDK:** Validates JWTs generated by the client. Role-based routing enforces separation between Customers, Providers, and Admins.
- **AI Service Layer (`aiProvider.js`):** Connects to Gemini API to parse natural language project requirements, generate deterministic match scores, and mediate DealRoom chats. Fully error-handled with a hardcoded fallback if Gemini times out or hits quotas.
- **Real-Time Websockets:** Firestore `onSnapshot` integrated into the React app to power a live chat DealRoom.
- **PayPal Service (`paypalService.js`):** Direct REST API calls (no bloated SDK on the server) to generate tokens, create Orders, capture them, and listen to Webhooks. Uses Sandbox environment.
- **Admin Dashboard:** Endpoints to aggregate real-time revenue and active users from Firestore via `count()` API to save costs.

## 2. Test Results & Hardening
- **Rate Limits:** Implemented on `/checkout` and `/ai` routes.
- **CORS:** Strictly tied to `CLIENT_ORIGIN`.
- **Payment Verification:** The amount cannot be manipulated by the client. The backend recalculates the 10% platform fee precisely and sends it to PayPal. Verification requires `COMPLETED` status.
- **Graceful Failures:** If PayPal declines the capture, the UI beautifully handles the error state.

## 3. Known Limitations / Future Polish
- **Payouts API:** We configured `PAYOUT_MODE=simulated` because PayPal sandbox accounts often require manual approval/configuration to use the actual Payouts API. The infrastructure is ready to flip to 'live' when approved.
- **Data Seed Scripts:** In a production launch, the emulator seed scripts would be migrated to a dedicated DB seeding job.

## 4. Manual Steps Needed for Live Production
- Configure a real Firebase project and download the `serviceAccountKey.json`.
- Get a Live PayPal Client ID & Secret.
- Enable Payouts API on the live PayPal account.
- Deploy the backend via the included `render.yaml`.
- Deploy the frontend to Vercel and set `VITE_USE_MOCK=false`.
